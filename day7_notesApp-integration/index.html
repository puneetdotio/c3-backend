Getting started with ImageKit

ImageKit ko samjho aur use karo

A beginner friendly guide for storing and serving images from your Node backend, built on top of what you already know about MongoDB and Multer.

Ye ek beginner friendly guide hai jisme sikhoge ki apne Node backend se images kaise store aur serve karte hain, wo bhi usi cheez ke upar jo tumhe pehle se pata hai, yaani MongoDB aur Multer.

Node.js Express Multer ImageKit SDK Postman
01
What is ImageKit?
A media storage and delivery service
Ek media storage aur delivery service

ImageKit is a cloud service that stores your images and videos for you and gives back a public URL for every file you upload. Instead of saving files on your own server, you send the file to ImageKit and it hands you a link that works from anywhere.

ImageKit ek cloud service hai jo tumhare images aur videos ko store karti hai aur har file ke liye ek public URL wapas deti hai. Apne server pe file save karne ke bajaye, tum file ImageKit ko bhej dete ho aur wo tumhe ek link de deti hai jo kahin se bhi chalta hai.

Think of it like

A locker room for your images. You drop the file inside, and you get a receipt (the URL) that opens that exact file for anyone, anytime.

Apni images ke liye ek locker room jaisa. File andar daal do, badle me ek receipt milti hai (URL) jo us exact file ko kabhi bhi, kahin se bhi khol deta hai.

You may have already stored files locally in the uploads folder using Multer. ImageKit replaces that local folder with a proper cloud storage and delivery network.

Tumne pehle Multer use karke files apne uploads folder me local store ki hongi. ImageKit us local folder ki jagah ek proper cloud storage aur delivery network deta hai.

MongoDB reminder: we never store the actual image file inside MongoDB. We only store the URL that ImageKit gives us, as a normal string field in our document.

MongoDB yaad dilaate hain: hum actual image file kabhi MongoDB me store nahi karte. Hum sirf wo URL store karte hain jo ImageKit deta hai, ek normal string field ki tarah apne document me.

Getting your Credentials
Three keys you will need before writing any code
Code likhne se pehle teen keys chahiye

To talk to ImageKit from your backend, you need three values, a public key, a private key and a URL endpoint. Here is how to get them.

Apne backend se ImageKit tak baat karne ke liye tumhe teen values chahiye, ek public key, ek private key aur ek URL endpoint. In ko nikalne ka tarika neeche hai.

1
Create an account

Go to imagekit.io and sign up for a free account using your email.

Account banao

imagekit.io pe jao aur apni email se ek free account bana lo.

2
Open the dashboard

After signing in, you will land on the ImageKit dashboard for your media library.

Dashboard kholo

Sign in karne ke baad, tum ImageKit ke dashboard pe pahunch jaoge, jaha tumhari media library hai.

3
Go to Developer Options

On the left side menu, find and click on Developer Options, this page holds your API keys.

Developer Options me jao

Left side menu me Developer Options dhoondo aur click karo, is page pe hi tumhari API keys milengi.

4
Copy the three values

You will see a Public Key, a Private Key and a URL Endpoint. Copy all three somewhere safe.

Teeno values copy karo

Tumhe ek Public Key, ek Private Key aur ek URL Endpoint dikhega. Teeno ko kahi safe jagah copy kar lo.

⚠

Never share your Private Key in your frontend code, GitHub repo or any public place. Anyone with this key can upload or delete files in your account. It always stays on the backend, inside your env file.

Apni Private Key kabhi share mat karo frontend code, GitHub repo ya kisi bhi public jagah pe. Ye key jiske paas hogi wo tumhare account me file upload ya delete kar sakta hai. Ye hamesha backend pe hi rehti hai, tumhari env file ke andar.

04
CORS Basics
Letting your frontend talk to your backend
Frontend ko backend se baat karne dena

CORS stands for Cross Origin Resource Sharing. By default, a browser blocks a request if your frontend and backend are running on different ports or domains. CORS is a setting on the backend that tells the browser which frontend origins are allowed to make requests.

CORS ka matlab hai Cross Origin Resource Sharing. Default me, browser ek request ko block kar deta hai agar tumhara frontend aur backend alag alag ports ya domains pe chal rahe hain. CORS ek setting hai backend pe, jo browser ko batati hai ki konse frontend origins se requests allow hain.

app.js
const cors = require('cors')

app.use(cors({
  origin: 'http://localhost:5173',
  credentials: true
}))

This tells the backend to accept requests only from that frontend URL. When you build your frontend later, just make sure the origin matches the port your frontend runs on.

Isse backend ko pata chal jata hai ki sirf usi frontend URL se aayi requests accept karni hain. Baad me jab tum frontend banaoge, bas dhyan rakhna ki origin wahi port ho jispe tumhara frontend chal raha hai.

Environment Variables
Keeping your keys out of the code
Apni keys ko code se door rakhna

Create a file named env at the root of your server folder and paste the three values you copied in section three.

Apne server folder ke root me ek file banao jiska naam env ho aur usme section teen wali teeno values paste kar do.

env
IMAGEKIT_PUBLIC_KEY=your public key here
IMAGEKIT_PRIVATE_KEY=your private key here
IMAGEKIT_URL_ENDPOINT=your url endpoint here
PORT=3000
💡

Also add this file to your gitignore so it never gets pushed to GitHub by mistake.

Is file ko apne gitignore me bhi add kar do, taaki galti se ye kabhi GitHub pe push na ho.

Step 1

multer.config.js

Same as before, memory storage, so the file stays in RAM as a buffer instead of being saved to disk. That buffer is what we send to ImageKit.

Pehle jaisa hi, memory storage, isse file disk pe save hone ke bajaye RAM me ek buffer ki tarah rehti hai. Wahi buffer hum ImageKit ko bhejte hain.

config/multer.config.js
const multer = require('multer')

const storage = multer.memoryStorage()

const upload = multer({ storage })

module.exports = upload
Step 2

imagekit.config.js

This creates one ImageKit instance using the three keys from our env file. We will reuse this instance everywhere we need to upload a file.

Ye hamare env file wali teeno keys use karke ek ImageKit instance banata hai. Isi instance ko hum har jagah reuse karenge jaha file upload karni ho.

config/imagekit.config.js
const ImageKit = require('imagekit')

const imagekit = new ImageKit({
  publicKey: process.env.IMAGEKIT_PUBLIC_KEY,
  privateKey: process.env.IMAGEKIT_PRIVATE_KEY,
  urlEndpoint: process.env.IMAGEKIT_URL_ENDPOINT
})

module.exports = imagekit
Step 3

user.controller.js

Instead of just logging the file like last time, we now upload the buffer to ImageKit and send back the URL it returns.

Last time jaisa sirf file ko console log karne ke bajaye, ab hum buffer ko ImageKit pe upload karte hain aur jo URL wapas milta hai wahi response me bhej dete hain.

controllers/user.controller.js
const imagekit = require('../config/imagekit.config')

const create = async (req, res) => {

  const file = req.file

  const uploadedFile = await imagekit.upload({
    file: file.buffer,
    fileName: file.originalname,
    folder: 'uploads'
  })

  res.status(201).json({
    message: 'file uploaded successfully',
    imageUrl: uploadedFile.url
  })
}

module.exports = { create }
💡

Notice we use req.file here, singular, because this route accepts one image at a time, unlike last class where we used req.files for multiple.

Yaha req.file use kiya hai, singular, kyunki ye route ek time pe ek hi image accept karta hai, last class ke req.files se alag jaha multiple images thi.

Step 4

user.routes.js

routes/user.routes.js
const express = require('express')
const { create } = require('../controllers/user.controller')
const upload = require('../config/multer.config')

const router = express.Router()

router.post('/create', upload.single('image'), create)

module.exports = router

app.js

app.js
const express = require('express')
const cors = require('cors')
require('dotenv').config()
const userRoutes = require('./routes/user.routes')

const app = express()

app.use(cors({
  origin: 'http://localhost:5173',
  credentials: true
}))

app.use(express.json())

app.use('/user', userRoutes)

module.exports = app

server.js

server.js
const app = require('./src/app')

app.listen(process.env.PORT || 3000, () => {
  console.log('server is running')
})

TL;DR
Everything in one glance
Yaad rakhne wali cheezein
  • ImageKit stores your files and gives you back a public URL
  • We never store the actual file in MongoDB, only the URL string
  • Get your Public Key, Private Key and URL Endpoint from Developer Options
  • Private Key always stays in the env file, never in the frontend
  • CORS on the backend decides which frontend origin can send requests
  • Multer with memory storage gives us a file buffer
  • That buffer is uploaded to ImageKit, which returns the URL
  • Test the route in Postman before building any frontend
  • ImageKit tumhari files store karta hai aur ek public URL wapas deta hai
  • Hum actual file kabhi MongoDB me store nahi karte, sirf URL string
  • Public Key, Private Key aur URL Endpoint Developer Options se milte hain
  • Private Key hamesha env file me rehti hai, frontend me kabhi nahi
  • CORS backend pe decide karta hai konsa frontend origin request bhej sakta hai
  • Multer memory storage se hume ek file buffer milta hai
  • Wahi buffer ImageKit pe upload hota hai, jo URL wapas deta hai
  • Koi bhi frontend banane se pehle route ko Postman me test karo
